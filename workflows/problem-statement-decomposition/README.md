# Problem Statement Decomposition Workflow

## Purpose

This workflow helps break down complex problem statements into manageable, analyzable components. It guides AI agents and business analysts through a systematic decomposition process.

## Workflow Steps

The workflow consists of sequential markdown files that should be executed in order:

1. **01-initial-assessment.md** - Initial problem statement capture and validation
2. **02-stakeholder-identification.md** - Identify key stakeholders and their perspectives
3. **03-problem-breakdown.md** - Decompose the problem into core components
4. **04-constraints-analysis.md** - Identify constraints, assumptions, and dependencies
5. **05-synthesis.md** - Synthesize findings into actionable insights

## How to Use

### For AI Agents
Execute each markdown file sequentially. Each file contains:
- **Context**: Background information and scope
- **Instructions**: Specific tasks to perform
- **Inputs**: Required information or data sources
- **Outputs**: Expected deliverables

### For Human Analysts
1. Review the problem statement you want to decompose
2. Work through each markdown file in numerical order
3. Document your findings at each step
4. Use the outputs to inform your analysis and recommendations

## Expected Outcomes

By completing this workflow, you will have:
- Clear understanding of the problem scope
- Identified stakeholders and their concerns
- Structured breakdown of problem components
- Documented constraints and dependencies
- Actionable insights for addressing the problem

## Customization

You can adapt this workflow by:
- Adding additional steps for domain-specific analysis
- Modifying existing steps to fit your context
- Incorporating organization-specific frameworks or methodologies
